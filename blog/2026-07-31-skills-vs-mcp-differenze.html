Skills vs MCP: due strumenti diversi per gli agenti AI

Non sono in competizione: risolvono due problemi diversi di chi costruisce con agenti AI, ed è utile sapere quale usare quando.

MCP: la presa elettrica verso il mondo esterno

Il Model Context Protocol (MCP) è uno standard che permette a un agente AI di collegarsi a dati e servizi esterni — un database, un sistema di ticket, un'API aziendale — con un'interfaccia uniforme, così non serve scrivere un'integrazione ad hoc per ogni strumento. Se hai letto il nostro articolo su MCP che diventa stateless, sai già che la specifica continua a evolversi rapidamente. Puoi immaginare MCP come la presa elettrica universale: definisce come l'agente "si collega" a un sistema esterno per leggere o scrivere dati, in modo standardizzato indipendentemente da chi ha costruito quel sistema.

Diciotto mesi fa MCP era la novità che tutti volevano integrare: ogni demo, ogni connettore per chatbot girava su MCP sotto il cofano. Il protocollo risolve un problema tecnico preciso — collegare l'agente al mondo esterno — ma non dice nulla su come l'agente debba comportarsi o quale procedura seguire per un compito specifico.

Skills: la procedura scritta in linguaggio naturale

Le Skills (competenze) affrontano un problema diverso: come insegnare a un agente un modo di lavorare, senza scrivere codice. Una Skill è un insieme di istruzioni in linguaggio naturale — cosa fare, in che ordine, quali errori evitare — che l'agente carica e segue quando il compito corrisponde. Non richiede API né server: un file di testo con istruzioni chiare basta a cambiare il comportamento dell'agente in modo affidabile e ripetibile.

La differenza pratica è chi può crearle: scrivere un server MCP richiede competenze di programmazione, scrivere una Skill richiede solo saper spiegare bene un processo. Questo apre la porta a chi non scrive codice — un product manager, un supporto clienti, chi conosce a fondo un processo aziendale — che può codificare la propria expertise in istruzioni che l'intero team, tramite i rispettivi agenti, può riutilizzare. Non a caso si dice che "il linguaggio di programmazione più richiesto oggi è l'inglese" (o l'italiano, per chi scrive in italiano): le Skills sono la prova concreta di questa idea.

Esempi pratici

  • Per tutti — Se usi un assistente AI per attività ripetitive (email, riassunti, ricerche), prova a scrivergli una "scheda di istruzioni" riutilizzabile con la procedura esatta che segui di solito, invece di ripetere lo stesso prompt lungo ogni volta: è l'idea di base delle Skills, applicabile anche senza strumenti tecnici.
  • Per chi programma — Usa MCP quando l'agente deve leggere o scrivere dati reali in un sistema esterno (un CRM, un tracker di bug, un database); usa una Skill quando vuoi che segua sempre la stessa procedura interna — checklist di code review, stile di commit, formato di un report — senza costruire un'integrazione. Spesso servono entrambi insieme: la Skill guida il "come", MCP fornisce il "con cosa".
